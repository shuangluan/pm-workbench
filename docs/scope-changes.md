# 相对 PRD v0.5 的范围变更

记录开发过程中经负责人确认、与 PRD v0.5 不同的决定。

## 2026-11-02 · 降低上手与录入门槛（M1.5）

负责人评审 M1 后确认：PM 自行在本地部署时，录入和导入门槛过高，必须让 PM 能直接体验主流程。

| 变更 | PRD v0.5 原文 | 现在 |
| --- | --- | --- |
| 截图导入需求 | “明确不做：OCR” | 支持粘贴、拖入或选择聊天截图，原图作为资料保存（按文件头识别类型，拒绝 SVG，哈希去重，随产品导出导入）。暂无模型时可手动转写；接入模型后由视觉模型读取截图、生成转写与拆分建议。 |
| 需求拆分 | F03 只描述 AI“建议拆分” | 先提供规则拆分（表格、聊天记录、“业务方：原话”、编号列表、段落），结果同样需要预览确认。模型拆分在 M2 输出相同结构。 |
| 表格导入 | 未列入 | 支持从 Excel/飞书直接粘贴表格，或上传 CSV；按表头识别业务方、标题、原话列。 |
| 报告建议 | 建议由 M2/M3 的模型步骤产生 | 新增“建议的下一步”：由已核对条目与已确认依赖确定性整理（需要决策 / 需要补充 / 需要验证 / 需要评审的建议）。方案层面的建议仍来自 M2/M3，并标为“建议”。 |
| 首次启动 | 终端提供一次性凭据 | 在交互式终端首次启动时直接显示初始化码；非终端环境（Docker、日志重定向）不显示，仍用 `npm run access:reset`。 |

### 截图的约束

- 转写是独立的资料，标明由用户或模型转写，并链接到原截图；引用指向转写文字，不冒充截图本身。
- 永久删除截图会同时删除原图文件与由它产生的转写。
- 接入模型后，截图会随任务发送给用户配置的模型服务，必须出现在“将发送的数据”提示中。

## 2026-11-03 · 许可证与公开

仓库公开，采用 AGPL-3.0-only（PRD §8.4 的推荐方案），并保留将来提供付费托管的可能。在接受第一份外部贡献前，需要决定是否把 PRD 中的 DCO 换成 CLA：DCO 下外部贡献的版权归贡献者，托管版若要包含不公开的修改，就需要 CLA 授予的额外权利。本节不构成法律意见。
